# Shared editing state

Status: accepted. Phase 1 implementation.

Electron main owns the project and history. Edits use a private working copy, runtime validation, then one commit and notification. A rejected edit leaves the project, revision, undo and redo unchanged. History stores complete project snapshots, following the [Redux past/present/future pattern](https://redux.js.org/usage/implementing-undo-history/) (MIT). ForgeCut does not need Redux as a dependency for this small backend service.

History is limited to 100 entries and 32 MiB of serialized before/after data. Contiguous changes with the same interaction ID share an undo entry. Undo and redo close that interaction. An entry larger than the budget is committed without retaining history. These limits describe serialized history data, not total process memory.

[Zod](https://zod.dev/basics) (MIT, pinned at 4.3.6) validates project files and command inputs. Domain validation additionally checks references, unique IDs, track kinds, overlap and source bounds. Existing simple string IDs remain readable for compatibility; newly generated IDs use UUIDs. IDs accept letters, numbers, dots, underscores, colons and hyphens and cannot contain path separators. Cache and autosave names hash input identities. Files retain snake_case and the existing tagged item variants. Unversioned files migrate to schema version 1; future versions are rejected.

Persistence follows same-directory temporary-file replacement, as used by [write-file-atomic](https://github.com/npm/write-file-atomic) (ISC). ForgeCut writes and syncs the temporary file, renames it, and syncs the directory on Linux. Saves are serialized and capture the project at invocation. A valid previous primary is first retained as `.forgecut.bak`; a corrupt primary cannot replace that recovery copy. Recovery is explicit. Missing media does not invalidate an otherwise valid project and is reported by asset ID.

`EditingService` has no Electron dependency. Its event sink carries export notifications and `AppState` publishes committed project snapshots. Electron IPC translates results into a serializable success/error union. The renderer subscribes before reading the initial snapshot, ignores older revisions and uses the same snapshot across its panels. Inspector edits use typed patches and a focus/pointer interaction ID; timeline moves and trims already commit only on mouse release. Revisions pause playback before the paused preview refreshes. Thumbnail/waveform caches follow media identity rather than every text edit, and late results cannot populate a different project's cache.

Revision-guarded synchronous batches use `apply_edits`, with session identity, expected revision and request ID. An isolated working owner reuses the existing command operations, then the real owner publishes one complete commit. Idempotent results are retained for up to 128 requests or 8 MiB of serialized snapshots. A retry within that window returns its original result; a reused ID with different validated contents fails. The window is in memory and does not survive restart. An MCP adapter must use this guarded path for creative edits. Async media commands stage all probe results before committing, check the originating session again, and merge into the current project. They are not part of synchronous batches.

The production editor now includes whole-project Undo/Redo buttons, editable project settings, missing-media relinking, visible command errors and an explicit recovery-copy action after an unsuccessful open. The transport adapter, session discovery and MCP server remain Phase 2 work. Canvas manipulation, font selection, Remotion templates and the code tab remain their later planned phases.
